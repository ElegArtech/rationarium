# Rationarium 1.0.0 — candidate

Préparation du 3 octobre 2026. La présence de ce fichier et du numéro dans les manifestes ne signifie pas que la version est publiée. Le bilan de stabilisation porte le verdict final.

## Depuis 1.0.0-rc.1

- Dépendances serveur et outils de test actualisés ; surcharges transitives ciblées et verrouillées.
- Image API limitée au graphe de production, avec moteur Prisma local et commandes de migration, amorçage, export et restauration.
- Bases Node et Caddy actualisées. Nouvelle image `rationarium-base` conservant PostgreSQL 18.6 et Debian Bookworm pour les volumes existants.
- Validation du tag et des références de version ; audits npm, scans système et recette d'installation avant publication.
- Archives Compose et hors ligne issues des mêmes images contrôlées, avec empreintes SHA-256.

Aucune migration du schéma métier n'est ajoutée par cette stabilisation. Le moteur PostgreSQL reste en version majeure 18 et le volume garde son emplacement. Les versions `rc.1` restent immuables.

## Mise à jour

1. Sauvegarder l'installation avec son script `sauvegarde.sh` et vérifier le manifeste d'empreintes. Conserver l'ancien kit et ses images.
2. Préparer le nouveau kit à côté de l'ancien ; reporter la configuration privée en conservant **le même `NOM_PROJET`**, les mots de passe, les certificats et les volumes. Régler `VERSION_RATIONARIUM=1.0.0`.
3. Charger les trois images du paquet hors ligne (`charger-images.sh`), ou les obtenir depuis le registre une fois publiées. Le service base référence désormais `rationarium-base:1.0.0`.
4. Lancer `docker compose up -d --wait`, puis vérifier la connexion, le planning, les documents et les courriels. Les services de migration et d'amorçage sont idempotents.
5. En cas d'échec, arrêter les services applicatifs, reprendre l'ancien kit et ses images, puis restaurer la sauvegarde complète selon le guide d'exploitation. Ne pas supprimer les volumes pour tenter de réparer une installation.

## Sécurité et limites

Le contrôle npm de production exige zéro alerte. Un avis braces reste qualifié dans l'outil de style de développement, absent de l'image API. Les avis système PostgreSQL résiduels restent visibles dans les rapports et disposent de qualifications temporaires, liées aux usages réels de l'image. Consulter `securite-exceptions.json` livré avec le kit et la décision technique. Une qualification n'est pas un correctif ; une modification des services, extensions, privilèges ou accès SQL impose de la réexaminer.

Le paquet hors ligne cible Linux x86-64. Les parcours d'accessibilité automatisés ne constituent pas une certification RGAA exhaustive. La recette locale ne remplace pas la vérification des paramètres propres au réseau d'installation.
