# Rationarium 1.0.0 — candidate

Préparation du 3 octobre 2026. La présence de ce fichier et du numéro dans les manifestes ne signifie pas que la version est publiée. Le bilan de stabilisation porte le verdict final.

## Depuis 1.0.0-rc.1

- Dépendances serveur et outils de test actualisés ; surcharges transitives ciblées et verrouillées.
- Image API limitée au graphe de production, avec moteur Prisma local et commandes de migration, amorçage, export et restauration.
- Bases Node et Caddy actualisées. Nouvelle image `rationarium-base` : PostgreSQL 18.6 sur Alpine 3.24, reconstruit sans XML/XSLT/LLVM, avec su-exec à la place de gosu ; scan nul complété par un contrôle des composants et versions corrigées.
- Validation du tag et des références de version ; audits npm, scans système et recette d'installation avant publication.
- Archives Compose et hors ligne issues des mêmes images contrôlées, avec empreintes SHA-256.

Aucune migration du schéma métier n'est ajoutée par cette stabilisation. Le moteur PostgreSQL reste en version majeure 18. Le passage de Debian à Alpine exige une migration logique dans un volume neuf ; voir [la procédure](../migration-postgresql.md). Ne pas réutiliser directement le volume rc.1. Les versions `rc.1` restent immuables.

## Mise à jour

1. Sauvegarder l'installation avec son script `sauvegarde.sh` et vérifier le manifeste d'empreintes. Conserver l'ancien kit et ses images.
2. Préparer le nouveau kit à côté de l'ancien ; reporter la configuration privée en conservant **le même `NOM_PROJET`**, les mots de passe, les certificats et les volumes. Régler `VERSION_RATIONARIUM=1.0.0`.
3. Charger les trois images du paquet hors ligne (`charger-images.sh`), ou les obtenir depuis le registre une fois publiées. Le service base référence désormais `rationarium-base:1.0.0`.
4. Exécuter `bash migrer-postgresql.sh ./migration-postgresql-1.0.0` selon la procédure dédiée. Le script restaure dans un volume neuf puis démarre la candidate. Vérifier la connexion, le planning, les documents et les courriels avant réouverture.
5. Avant réouverture, le script `retour.sh` produit dans le dossier de migration restaure les anciennes images et le volume source conservé. Après reprise des utilisateurs, traiter d’abord les écritures nouvelles. Ne supprimer aucun volume pour tenter de réparer une installation.

## Sécurité et limites

Le contrôle npm de production exige zéro alerte. Un avis braces reste qualifié dans l'outil de style de développement, absent de l'image API. L'image web conserve un avis UNKNOWN. PostgreSQL exige désormais zéro avis de toute gravité : les 118 exceptions initiales sont supprimées après remplacement effectif des composants. Voir [la sécurité de livraison](../securite-livraison.md).
