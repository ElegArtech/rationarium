# Rationarium 1.1.0

Version fonctionnelle qui suit [1.0.2](1.0.2.md). Elle ajoute l'assistant de suivi, un module facultatif et
désactivé par défaut, et corrige les avis de sécurité publiés depuis 1.0.2 sur les dépendances et sur
l'image web. **Toutes les installations 1.0.x doivent être mises à jour.**

Une migration est appliquée automatiquement au démarrage. Les fichiers du kit changent : il faut les
remplacer, pas seulement les images.

## Assistant de suivi (M22)

Un agent, qui tourne sur le poste d'un utilisateur avec son propre client de modèle de langage et
son propre abonnement, met à jour les projets, les jalons, les tâches, les événements et les temps à
partir des sources déclarées : courriel, documents, dépôts, messageries, publications. Il agit
directement, sans validation préalable. Chaque action est tracée avec ses preuves et se défait.

- Le module est **désactivé par défaut**. Désactivé, il n'a ni écran, ni traitement planifié, ni
  route hors de ses réglages et de sa sonde d'état. Il s'active dans Paramétrage › Assistant.
- Un agent se branche par un **jeton** créé dans Mon compte › Agents. Seule son empreinte est
  stockée ; il expire au bout d'un an, se révoque, et n'agit qu'avec les droits de son propriétaire.
- L'agent joint le guichet `/api/agent/v1`. **Chaque action rejoue la route d'écriture habituelle**,
  au nom du propriétaire du jeton : les droits, le périmètre, les règles métier et l'audit sont ceux
  d'une saisie directe ([décision](../adr/ADR-20261103-assistant-appels-internes.md)).
- Les règles du suivi sont tenues par le serveur : une tâche de projet porte un jalon, un projet
  commence à une date attestée par une preuve, aucune entité ne se désigne par ressemblance, et
  l'agent ne supprime rien.
- L'écran **Activité de l'agent** montre chaque action, avec l'état avant et après, sa justification
  et ses preuves, et permet de la défaire. La fiche projet gagne un onglet **Suivi** : ce que l'agent
  surveille pour ce projet.
- Le serveur **n'appelle aucun service extérieur** : le modèle de langage reste sur le poste. Un
  agent de référence est fourni dans `outils/agent/`, avec des consignes pour Claude Code et Codex.

Deux permissions s'ajoutent : `assistant:use`, donnée aux rôles qui conduisent ou encadrent des
projets, et `assistant:configure`, réservée à l'administrateur. Les rôles système les reçoivent au
démarrage ; un rôle personnalisé les reçoit depuis la matrice des rôles.

La spécification est dans [docs/assistant/SPEC-PHASE-1.md](../assistant/SPEC-PHASE-1.md).

## Sécurité

- Les dépendances signalées depuis 1.0.2 passent à leurs versions corrigées : fastify, zod,
  nodemailer, fast-uri, ip-address, seroval, undici, vite et vitest. `nestjs-zod`, inutilisé, est
  retiré.
- L'image web embarque Caddy 2.11.7 recompilé avec Go 1.27.3, `golang.org/x/net` 0.62.0 et `go-jose`
  4.1.6, et ses paquets Alpine sont mis à jour à la construction.
- Restent qualifiés jusqu'au 3 décembre 2026, avec leur motif dans
  `deploiement/securite-exceptions.json` : `minimatch` et `glob`, employés seulement par l'outillage
  de développement, et `go-jose` v3 dans Caddy, sans version corrigée publiée et tiré seulement par
  un serveur ACME que le Caddyfile n'active pas.

## Mise à jour depuis 1.0.x

1. Sauvegarder l'installation avec `sauvegarde.sh`.
2. Remplacer les fichiers du kit par ceux de 1.1.0, **en conservant `.env`, les certificats et les
   sauvegardes**.
3. Régler `VERSION_RATIONARIUM=1.1.0` dans `.env`. Depuis 1.0.0 ou 1.0.1, suivre aussi l'étape 3 des
   [notes de 1.0.2](1.0.2.md#mise-à-jour-depuis-100-ou-101).
4. Charger les images du paquet hors ligne (`charger-images.sh`) ou les obtenir depuis le registre,
   puis `docker compose up -d --wait`.

La migration `20261102120000_assistant_de_suivi` crée les quatre tables du module ; elle ne modifie
aucune table existante. Le module reste désactivé tant qu'un administrateur ne l'active pas.
